0. Introduction — Why Run LLMs Locally?

Welcome. This manual is written for anyone who has heard about AI, maybe played with a chatbot in a browser, and now wonders: "Can I run this on my own computer?"

The short answer is: yes. And for many people, running models locally is the better way to start.

What "local" means. When you use a chatbot on a website, your message travels to a company's server and an answer comes back. Your words leave your computer. When you run an LLM locally, the model lives on your machine and thinks using your processor and/or graphics card. Your messages never leave your house. No account. No monthly fee. No internet required after you download the model once.

Who this is for. People curious about AI who want privacy and no subscriptions; writers, students, and small-business owners who want a tool they control; anyone on a slow or metered connection; healthcare workers and educators exploring AI safely (educational use only—never medical advice).

1. Choosing a Model

There are thousands of models. For a beginner, the choice comes down to one practical question: will it run on my computer?

Models are sized by parameters—the internal "knobs" the model adjusts while learning. You will see names like 1B (1 billion), 3B, 8B, and 70B. Bigger is generally smarter, but bigger also needs more memory and runs slower. For everyday writing, summarizing, and coding help, an 8B or 14B model is often more than enough.

Model familyTypical sizesGood forNotes
Llama 3.21B, 3BFast chat on low-end machinesVery beginner-friendly
Llama 3.18B, 70BStrong general assistant8B fits many home PCs
Phi-3 / Phi-43.8B, 14BCoding and reasoningEfficient, from Microsoft
Qwen 2.51.5B, 7B, 32BMultilingual, codingStrong small models
Gemma 22B, 9B, 27BGeneral useFrom Google, efficient
TinyLlama1.1BOld or weak hardwareBasic, slow, but tiny

Where to get models: Ollama library, Hugging Face, or LM Studio's built-in model discoverer. Start small—download a 1B or 3B model first, confirm it runs, then move up.

Your first model: try Llama 3.2 3B (about 2 GB at 4-bit). It runs on most computers with 8 GB of RAM and answers quickly. If that goes well, try Llama 3.1 8B if your machine has the memory.

2. RAM/VRAM Math — Will It Fit?

A model needs to live in memory while it runs. That memory is either VRAM (graphics card memory, fastest) or RAM (main memory, slower but usually larger). If the model does not fit, it will refuse to start, crawl, or force your operating system to swap to disk.

Step 1: estimate the model's weight size

PrecisionBytes per parameterWhat it means
FP324 bytesFull precision; rarely needed locally
FP16 / BF162 bytesHalf precision; good quality
INT81 byte8-bit quantization; small quality loss
INT4 / 4-bit0.5 byte4-bit quantization; great for home PCs

Rule of thumb: size in GB ≈ parameters × bytes per parameter ÷ 1 billion.

ModelPrecisionWeight size
Llama 3.1 8B4-bit~4 GB
Llama 3.1 8B8-bit~8 GB
Llama 3.1 70B4-bit~35 GB
TinyLlama 1.1B4-bit~0.55 GB

Step 2: add overhead

You also need room for the KV cache (short-term conversation memory), the operating system, and other apps. A practical rule: budget model weights + 2–3 GB overhead.

Step 3: compare to what you have

If you only remember one thing: start small, measure what actually fits, and move up only if you have headroom.

3. Quantization Explained

Quantization compresses a model's numbers, the way a JPEG compresses a photo—it throws away detail you barely notice, so the file takes far less space.

Instead of storing every weight with high precision (FP16, 2 bytes), you can store them at INT8 (1 byte) or INT4 / 4-bit (0.5 byte). Without quantization, an 8B model needs ~16 GB just for weights—too much for most home computers. At 4-bit, it needs ~4 GB.

The tradeoff: the more you compress, the more the model's reasoning can dull on hard math or nuanced writing. For everyday chat, summarization, and coding help, 4-bit is usually indistinguishable.

Local tools usually use GGUF files. You will see names like llama-3.2-3b-instruct-q4_k_m.gguf. The suffix tells you the quantization:

SuffixMeaningBest for
Q4_K_M4-bit, medium qualityDaily use on home PCs (recommended start)
Q8_08-bitNear-original quality, needs more RAM
FP16No quantizationBest quality, needs a lot of RAM
How to choose: start with Q4_K_M. If it feels too dim-witted, try Q8_0—if you have the memory. If Q4_K_M does not fit, try a smaller model before a bigger one with heavier quantization.

4. Ollama Setup

Ollama is the friendliest way to run local LLMs: one download, one command, and you are chatting with a model on your own machine.

Step 1: install Ollama

  1. Go to ollama.com and download the installer for Windows, Mac, or Linux.
  2. Run the installer, then open a terminal and confirm: ollama --version

Step 2: run your first model

ollama run llama3.2:1b

The first time, Ollama downloads the model (~1–2 GB). After that it runs offline. Type a message and press Enter. Type /bye to exit.

Step 3: try a bigger model

ollama pull llama3.2:3b
ollama run llama3.2:3b
CommandWhat it does
ollama listShows downloaded models
ollama psShows running models and speed
ollama pull <name>Downloads a model
ollama rm <name>Deletes a model to free space

Models are stored in ~/.ollama/models (Mac/Linux) or %USERPROFILE%\.ollama\models (Windows). They can be several gigabytes each—watch your disk space.

5. LM Studio Setup

LM Studio is a polished desktop app with a visual interface. Good if you prefer clicking over typing, or want to compare several models side by side.

  1. Download and install from lmstudio.ai.
  2. Click Discover, search for a model (try Llama 3.2 3B), pick a 4-bit / Q4_K_M version, and click Download.
  3. Click Chat, choose your model from the picker, and start typing.

GPU offload slider: decides how much of the model goes to your graphics card versus main memory. Start in the middle. If chats are slow, slide right. If the app crashes, slide left.

Local server: LM Studio can run a local API server at http://localhost:1234 so other programs can talk to your model like a cloud API—but everything stays on your machine.

6. llama.cpp Setup

llama.cpp is the engine under the hood of many local LLM tools. It is fast and runs on almost any hardware. Using it directly is for maximum control.

git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp
make llama-cli

Then run a GGUF model:

./llama-cli -m models/llama-3.2-3b-instruct-q4_k_m.gguf -p "Hello, who are you?"

With an NVIDIA GPU, rebuild with LLAMA_CUDA=1 for speed. llama.cpp also includes llama-server, a local API server at an address you choose.

Ollama and LM Studio use llama.cpp-compatible engines under the hood. Start with Ollama or LM Studio; come here when you want maximum control or a local server.

7. Measuring Speed

Speed decides whether a local LLM feels useful or frustrating.

MetricWhat it means
Tokens per second (t/s)How fast the model writes after it starts. Above ~3 t/s feels conversational; below ~1 t/s feels slow.
Time to first token (TTFT)How long from pressing Enter until the first character appears.

How to measure: Ollama → ollama ps; llama.cpp → it prints t/s at the end; LM Studio → live readout in the chat panel.

A quick measurement: ollama run llama3.2:3b "Write a 200-word story about a robot learning to garden." then check ollama ps in another terminal.

SetupTypical speed
3B model, 4-bit, CPU only1–4 t/s
8B model, 4-bit, CPU only0.5–2 t/s
8B model, 4-bit, GPU offloaded5–20+ t/s

A token is about 0.75 words in English, so 10 t/s ≈ 7–8 words per second.

8. Privacy

Privacy is the main reason people run AI locally. Once a model is downloaded:

  • Your prompts and the model's answers never leave your computer.
  • No company sees your writing, code, or notes.
  • You can disconnect the internet and the model keeps working.

What touches the internet: downloading the model the first time, and (optionally) checking for app updates. Turn off cloud features if you want full privacy.

Important limits: local AI keeps your data on your machine, but it does not make the model trustworthy. Models hallucinate, reflect bias, and can give wrong answers. Always verify important information yourself. This guide is educational only—not medical advice. Never use it for actual patient decisions without professional oversight.

9. Cloud vs. Local — When to Use Which

LocalCloud subscription
Ongoing cost$0$0–$30/month
Hardware costUses what you ownNone
Internet after downloadNoneRequired every message
PrivacyYou control itProvider sees input

Use local when: privacy matters, no monthly bill, spotty internet, learning and experimenting.

Use cloud when: you need the smartest model for a one-off task, your hardware cannot run even a small model, or you need features local tools do not offer.

Many people use both: a small local model for daily work, and a cloud model for occasional heavy lifting. You do not have to choose one forever.

10. Worked Examples

Example A — MacBook Air, M2, 8 GB RAM

Unified memory: model and macOS share 8 GB.

  • Model: Llama 3.2 3B at 4-bit (~2 GB weights)
  • Tool: Ollama
  • Command: ollama run llama3.2:3b
  • Expected speed: 3–6 t/s

Fits? Yes, comfortably.

Example B — Windows PC, RTX 3060, 12 GB VRAM, 32 GB RAM

  • Model: Llama 3.1 8B at 4-bit Q4_K_M (~4–5 GB weights)
  • Tool: LM Studio or Ollama
  • Expected speed: 10–20 t/s

Fits? Yes, easily.

Example C — Old laptop, 16 GB RAM, no dedicated GPU

  • Model: TinyLlama 1.1B or Phi-3.5 mini 3.8B at 4-bit
  • Tool: Ollama
  • Expected speed: 1–3 t/s

Fits? Yes. Keep context short.

Worksheet for your own computer

  1. Total RAM: ______ GB
  2. Dedicated VRAM: ______ GB, or "none/shared"
  3. Model you want: ______ (size in B)
  4. Quantization: Q4_K_M
  5. Weight size: params × 0.5 = ______ GB
  6. Plus overhead (+2–3 GB): ______ GB total
  7. Does total fit in your RAM/VRAM? Yes / No

If No: pick a smaller model or heavier quantization, then redo the math.

11. Checklists

Before you download

  • I know my computer's total RAM
  • I know whether I have a dedicated GPU and how much VRAM it has
  • I picked a model small enough to fit
  • I chose Q4_K_M quantization to start
  • I have enough free disk space

After setup

  • The model downloads and runs without error
  • I sent a test message and got an answer
  • I checked the speed (tokens per second)
  • I know how to stop or unload the model
  • I know where the model files live on my disk

Privacy check

  • I tested the model while offline
  • I did not paste real passwords or patient records
  • I downloaded from a trusted source
  • I know how to delete the model and chat history

Speed check

  • I measured tokens per second
  • Speed is above ~1 t/s (usable)
  • I closed other heavy apps before measuring
